# 班级管理插件（class_manager）v1.5.3

AstrBot 班级群管理插件：平台自适配禁言、智能降级惩罚、智能菜单、免 @ 触发、
聊天模式与身份展示，覆盖签到、积分、商城、等级称号、抽奖、任务、成就、转账与完整群管功能。

- 插件名：`class_manager`
- 显示名称：班级
- 版本：`1.5.3`
- 作者：辞忧
- 适用：AstrBot 4.x

## v1.5.3 更新：禁言修复与平台适配

### 1. 平台适配层

新增 `platform_adapter.py`，运行时自动识别当前平台，并据此选择禁言实现：

| 平台 | 识别特征 | 禁言 | 解禁 | 踢出 | 撤回 |
| --- | --- | --- | --- | --- | --- |
| OneBot（NapCat / go-cqhttp / Lagrange） | `aiocqhttp`、`napcat`、`onebot` 等 | ✅ `set_group_ban` | ✅ `duration=0` | ✅ | ✅ |
| Telegram | `telegram` / `tg` | ✅ `restrict_chat_member` | ✅ `until_date=0` | ❌ | ❌ |
| QQ 官方机器人 | `qq_official` / `qqofficial` | ❌ 无接口 | ❌ | ❌ | ❌ |
| 其他 / 未知平台 | 无法识别 | ❌ | ❌ | ❌ | ❌ |

调用采用鸭子类型：优先直接调用 `bot.set_group_ban(...)`，失败则回退
`bot.call_action("set_group_ban", ...)`；每组参数变体依次尝试，兼容不同
OneBot 实现的参数差异，全部失败时返回最后一次错误。

### 2. 指令与平台限制

| 指令 | 说明 | 平台限制 |
| --- | --- | --- |
| `/禁言 @某人 时长` | 禁言成员（时长单位：分钟，省略则用 `mute_duration`） | QQ 官方不可用 |
| `/解除禁言 @某人` | 解除禁言 | QQ 官方不可用 |
| `/警告 @某人 原因` | 记录警告 | 所有平台可用 |
| `/积分惩罚 @某人 数量 [原因]` | 扣除积分 | 所有平台可用 |
| `/平台信息` | 查看当前平台支持的权限功能 | 所有平台可用 |
| `/惩罚记录 @某人` | 查看成员惩罚历史（普通成员仅可查自己） | 所有平台可用 |
| `/手动惩罚 @某人 类型 [时长]` | 手动执行警告 / 扣分 / 黑名单 | 所有平台可用 |

### 3. 智能降级

平台不支持禁言（如 QQ 官方机器人）时，不再直接报错，而是自动降级：

```
用户：/禁言 @张三 10
机器人：⚠️ 当前平台不支持直接禁言

已自动降级为以下惩罚：
- 记录警告 1 次
- 扣除积分 5 分

管理员可手动在 QQ 群中禁言该成员
```

- 降级行为由 `punishment.fallback_to_warning` 控制；
- 扣分数量取 `punishment.points_deduction`；
- 累计警告达到 `punishment.warning_threshold`（默认 3 次）时，会额外提醒管理员手动处理；
- 设为 `false` 时仅提示管理员，不写入警告与扣分。

### 4. 违规处理流程

```
检测到违禁词 / 违规行为
    ↓
平台支持禁言？
    ↓是                    ↓否
自动禁言              记录警告 + 扣积分
    ↓                    ↓
通知管理员            累计 3 次警告？
    ↓                    ↓是
记录到数据库          通知管理员手动处理
```

### 5. 修复 `MessageChain has no len()`

`/发布公告` 在 QQ 官方平台会触发：

```
TypeError: object of type 'MessageChain' has no len()
```

原因：`event.chain_result()` 内部会对 `result.chain` 执行 `len()`，
而代码传入的是 `MessageChain` 对象本身。现已改为传入 `chain.chain`（组件列表）：

```python
chain = MessageChain()
chain.at("全体成员", "all")
chain.message("📢 群公告 ...")
yield event.chain_result(chain.chain)   # 正确：传组件列表
```

> 编写第三方插件时同样注意：只要使用 `event.chain_result(...)`，
> 请传 `chain.chain`，不要传 `MessageChain` 对象本身。
> `context.send_message(umo, chain)` 则可以直接传 `MessageChain`。

## v1.5.1 三项关键修复

### 1. 阻断 LLM，支持双模式切换

v1.5.0 中，用户 @机器人 或使用指令时，消息会同时触发插件和调用 LLM，
导致机器人重复回复或答非所问。v1.5.1 通过 `event.stop_event()` 阻断插件已处理的消息，
并新增聊天模式，让「插件指令」和「AI 自由聊天」互不干扰。

| 模式 | 触发方式 | 处理方式 |
| --- | --- | --- |
| 插件模式 | 指令、关键词、菜单数字 | 插件处理，**阻断 LLM** |
| 聊天模式 | `/聊天`、`/ai`、`#` 前缀 | 去掉前缀后**直接交给 LLM** |

**一次性聊天**（去掉前缀后转给 LLM）：

```
/聊天 你好，今天天气怎么样
/ai 帮我写一首关于秋天的诗
# 什么是量子力学
```

**持续聊天模式**（只发送前缀进入，之后每条消息都交给 LLM）：

```
用户：/聊天
机器人：🤖 已进入 AI 聊天模式
        直接输入消息即可对话
        输入“退出”或 30 秒无操作自动退出

用户：你好
机器人：（LLM 回复）

用户：退出
机器人：👋 已退出 AI 聊天模式
```

- 退出词：`退出`、`退出聊天`、`结束聊天`、`结束`、`再见`、`拜拜`；
- 超时时间由 `chat_timeout` 控制，默认 30 秒无操作自动退出；
- 聊天模式中提到精确功能词（如「签到」「积分」）时，执行该功能并退出聊天模式；
- `/` 前缀仍交给 AstrBot 指令系统，`！` 前缀仍作为插件指令前缀；
- `#` 在 v1.5.1 中默认属于聊天模式前缀，可在 `chat_prefixes` 中调整。

**智能自动识别**（`auto_detect: true`）：

| 用户消息 | 处理 |
| --- | --- |
| `签到` | 匹配指令 → 插件处理并阻断 LLM |
| `你好` | 未匹配，属于问候 → 交给 LLM |
| `今天天气怎么样` | 未匹配，属于疑问句 → 交给 LLM |
| `帮我写首诗` | 未匹配，属于请求句 → 交给 LLM |
| `哈哈哈` | 未匹配，无意义 → 静默阻断，不打扰 LLM |

`block_llm: false` 可关闭阻断（插件仍会回复，但消息也会继续传给 LLM）。

## 配置说明

配置文件位于插件目录 `config.yaml`，保存后自动生效（热更新）。

```yaml
# 免 @ 触发
trigger_mode: "all"          # all / command / keyword
menu_style: "category"       # category / flat
cooldown_seconds: 3          # 同一用户触发间隔（秒），0 表示关闭
session_timeout: 30          # 上下文/会话有效期（秒）
context_timeout: 30          # 旧字段，兼容保留；同时存在时以 session_timeout 为准
admin_bypass: true           # 管理员是否绕过频率限制

# v1.5.1 新增
block_llm: true              # 插件处理的消息阻断 LLM，避免重复回复
smart_menu: true             # 意图识别、错别字纠正、未知指令推荐
identity_display: true       # 个人中心与排行榜显示身份
auto_detect: true            # 疑问句/请求句交给 LLM
chat_prefixes: ["/聊天", "/ai", "#"]   # 聊天模式前缀
chat_timeout: 30             # 聊天模式超时（秒）

# v1.5.3 新增
punishment:
  auto_mute: true            # 平台支持时自动禁言
  mute_duration: 10          # 默认禁言时长（分钟）
  warning_threshold: 3       # 警告阈值，达到后提醒管理员

  fallback_to_warning: true  # 不支持禁言时降级为警告 + 扣分
```

| 配置项 | 取值 | 说明 |
| --- | --- | --- |
| `trigger_mode` | `all` / `command` / `keyword` | 全局默认触发方式 |
| `menu_style` | `category` / `flat` | 分类二级菜单 / 平铺菜单 |
| `cooldown_seconds` | 0~60 | 同一用户最短触发间隔 |
| `session_timeout` | 5~600 | 上下文与会话有效期 |
| `context_timeout` | 5~600 | 旧版字段，兼容保留 |
| `admin_bypass` | `true` / `false` | 管理员是否绕过频率限制 |
| `block_llm` | `true` / `false` | 插件处理消息后是否阻断 LLM |
| `smart_menu` | `true` / `false` | 是否启用意图识别、纠错与推荐 |
| `identity_display` | `true` / `false` | 是否显示群主/管理员/成员身份 |
| `auto_detect` | `true` / `false` | 未匹配的问句/请求是否交给 LLM |
| `chat_prefixes` | 字符串列表 | 聊天模式前缀 |
| `chat_timeout` | 5~600 | 聊天模式超时 |
| `punishment.auto_mute` | `true` / `false` | 平台支持时是否自动禁言 |
| `punishment.mute_duration` | 1~43200 | 默认禁言时长（分钟） |
| `punishment.warning_threshold` | 1~20 | 累计多少次警告后提醒管理员 |
| `punishment.points_deduction` | 0~1000 | 违规默认扣分，0 表示不扣 |
| `punishment.fallback_to_warning` | `true` / `false` | 不支持禁言时是否降级惩罚 |

> 群内 `/触发模式` 设置优先于全局 `trigger_mode`；恢复默认后重新跟随配置。

## 免 @ 触发

插件监听所有群消息，无需 @机器人。触发优先级从高到低：

1. **聊天模式前缀**：`/聊天`、`/ai`、`#`（交给 LLM）
2. **指令前缀**：`/签到`、`！签到`
3. **精确关键词**：消息等于「签到」「积分」「商城」等
4. **模糊关键词 / 自然语言**：「我要签到」「查一下积分」「我想看看我有多少分」
5. **上下文数字**：菜单或商城中的编号
6. **@ 触发**：保留兼容

普通聊天不会触发：只有匹配菜单、关键词或当前上下文的数字才响应；
超过 30 字的长消息不参与模糊匹配，避免误触。

管理员可按群设置触发方式：

```
/触发模式           查看当前触发方式
/触发模式 全部      指令 + 精确关键词 + 模糊关键词
/触发模式 指令      仅响应 /、！开头的指令
/触发模式 关键词    仅响应关键词（无需前缀）
/触发模式 默认      恢复为 config.yaml 的全局设置
```

## 防刷屏机制

- 同一用户 3 秒内最多触发 1 次；
- 连续 5 次快速触发后进入 60 秒冷却（1 次成功 + 4 次被拦截）；
- 群主/管理员默认不受限制，可在 `config.yaml` 中关闭 `admin_bypass`；
- 冷却期间静默忽略，只在进入冷却时提示一次。

- 自动审核默认全部关闭，需管理员手动开启；
- 检测在主流程完成，撤回/禁言/踢出等平台操作在后台异步执行，不阻塞聊天响应；
- 禁言/解禁统一走 `PlatformAdapter`，平台不支持时自动降级为警告 + 扣分；
- 命中违规的消息不参与聊天积分统计；
- 白名单成员、群主、管理员免检。

## 安装

1. 将 `class_manager` 目录放入 `AstrBot/data/plugins/`；
2. 启动或重载 AstrBot；
3. 在群内发送 `帮助` 或 `/帮助` 验证是否生效。

插件首次启动会自动创建 `data/class_manager.db` 与全部数据表，无需手动初始化。

## 从 v1.5.2 升级到 v1.5.3

1. 停止 AstrBot，备份旧数据库 `data/class_manager.db`；
2. 用 v1.5.3 文件覆盖插件目录（**保留原 `data/` 文件夹**）；
3. 可选：执行迁移脚本提前确认结果：

   ```bash
   cd AstrBot/data/plugins/class_manager
   python migrate.py
   ```

   脚本默认迁移 `data/class_manager.db`，并自动生成 `.bak-时间戳` 备份；
   也可以指定路径：`python migrate.py /path/to/class_manager.db`。

4. 启动 AstrBot。即使不手动执行脚本，插件加载时也会自动建表、补列并初始化默认数据。

v1.5.3 数据库结构无变化，签到、积分、商城、抽奖、任务、成就、转账与群管数据
全部原样保留。`config.yaml` 新增 `punishment` 配置段，旧配置可继续使用，
缺失项自动采用默认值（`auto_mute: true`、`mute_duration: 10`、
`warning_threshold: 3`、`points_deduction: 5`、`fallback_to_warning: true`）。

> 升级提示：QQ 官方机器人本身没有禁言接口，v1.5.3 不再报错，
> 而是提示管理员并降级为警告 + 扣分。若希望完全关闭降级，
> 将 `punishment.fallback_to_warning` 设为 `false`。

## 迁移脚本做了什么

1. 自动识别 v1.0.0 至 v1.5.3 数据库；
2. 创建缺失的商城、成长与群管数据表；
3. 补齐 `users.exp` / `users.level` / `users.title`；
4. 补齐 `group_settings.defaults_seeded` / `trigger_mode`；
5. 写入默认成就，为已有群初始化默认每日任务；
6. 为已有群写入默认自动审核配置（全部关闭，不覆盖已有配置）；
7. 按经验值重算等级与称号；
8. 执行 `PRAGMA integrity_check` 完整性检查。

## 常见问题

**Q：为什么机器人回复了两次？**
A：v1.5.3 默认 `block_llm: true`，插件处理的消息会阻断 LLM。若仍重复，
请确认使用的是 v1.5.3 并重载插件；若你希望插件与 LLM 同时响应，可设为 `false`。

**Q：怎么和 AI 自由聊天？**
A：发送 `/聊天 你好` 一次性对话；或只发送 `/聊天` 进入持续聊天模式，
之后直接输入消息即可，输入「退出」结束。也可使用 `/ai`、`#` 前缀。

**Q：为什么我发「#签到」没有签到？**
A：`#` 默认是聊天模式前缀。请改用 `签到`、`！签到` 或 `/签到`；
或从 `config.yaml` 的 `chat_prefixes` 中移除 `#`。

**Q：为什么发送“签到”没有反应？**
A：确认本群触发方式不是「仅指令」；可发送 `/触发模式` 查看，或直接用 `/签到`。

**Q：普通聊天会不会误触发？**
A：只有精确关键词、模糊关键词或上下文数字才响应；超过 30 字的长消息不参与模糊匹配。

**Q：为什么连续发指令没有回应？**
A：触发了防刷屏限制。同一用户 3 秒内最多触发 1 次，连续 5 次快速触发会冷却 60 秒；
管理员默认不受限制。

**Q：个人中心身份显示为普通成员？**
A：身份来自平台事件或 `get_group_member_info`，若平台未提供角色信息会降级显示。
确认机器人与平台连接正常，且群号、成员号有效。

**Q：自动审核为什么没有生效？**
A：自动审核默认关闭，请先用 `/开启防刷屏`、`/开启防广告` 或 `/开启夜间模式` 开启；
同时确认机器人是管理员且拥有禁言/踢人权限。

**Q：群管操作没有执行？**
A：禁言/解禁由 `PlatformAdapter` 按平台自动选择接口：
OneBot 走 `set_group_ban`，Telegram 走 `restrict_chat_member`，
QQ 官方机器人没有禁言接口。可发送 `/平台信息` 查看当前平台支持的能力；
失败时会记录日志并提示，不会崩溃。

**Q：QQ 官方机器人为什么不能禁言？**
A：QQ 官方机器人 API 未开放群禁言能力。v1.5.3 遇到 `/禁言` 时会自动降级为
「记录警告 + 扣除积分」，并提示管理员在 QQ 群后台手动禁言。
累计警告达到 `warning_threshold` 后会额外提醒管理员。

**Q：自动审核在 QQ 官方平台怎么处罚？**
A：同样走降级流程：记录警告 + 扣分，不会因为调用不存在的禁言接口而报错。

**Q：修改 config.yaml 需要重启吗？**
A：不需要。保存后下一次触发时自动重新加载；若同时用 `/触发模式` 设置了本群方式，
群设置优先于全局配置。

**Q：如何备份数据？**
A：停止 AstrBot 后复制 `data/class_manager.db` 即可；迁移脚本也会自动生成备份。
